The Crystallize MCP Server lets AI agents interact with your Crystallize tenant through the [Model Context Protocol](https://modelcontextprotocol.io/). It runs on Cloudflare Workers and provides authenticated access to query and mutate your Crystallize data.

## What You Can Do

    <Card title="Query Data" icon="magnifier">

## Setup

<Steps>
1. **Generate Access Tokens**

    In the Crystallize Admin, create a new User with a **Read-Only Role** and generate Access Tokens for that user.

    > We recommend starting with read-only access. You can create a separate user with write permissions if you need mutation capabilities.

2. **Install the MCP Server**

    Use `add-mcp` to register the server with your AI client:

    ```bash
    npx add-mcp https://mcp.crystallize.com/mcp \
        --header "X-Crystallize-Access-Token-Id: ACCESS_TOKEN_ID" \
        --header "X-Crystallize-Access-Token-Secret: ACCESS_TOKEN_SECRET"
    ```

    This works with any MCP-compatible client (Claude Desktop, Claude Code, Cursor, Windsurf, etc.).

3. **Verify the connection**

    Ask your AI agent to list the available tools — you should see the Crystallize tools ready to use.

</Steps>

## Available Tools

The following tools are auto-generated from the [MCP Server source code](https://github.com/crystallizeapi/ai/tree/main/use-crystallize/mcp-servers/crystallize/src/core/mcp/tools).

<McpTools />

The server is **read-only by default**. The following query parameters can be appended to the server URL to change which tools are exposed:

| Query parameter      | Default | Effect                                                                                              |
| -------------------- | ------- | --------------------------------------------------------------------------------------------------- |
| `exposeWrite=true`   | off     | Exposes the write tools (mutations and mass operations). Off by default for safety.                 |
| `exposeSkills=false` | on      | Hides the `skills` tool — useful if you already have Skills installed (e.g. via the Claude Plugin). |
| `exposeUi=false`     | on      | Hides UI-panel tools (`tenant-overview`, `product-overview`).                                       |

For example, to enable writes:

```bash
npx add-mcp "https://mcp.crystallize.com/mcp?exposeWrite=true" \
    --header "X-Crystallize-Access-Token-Id: ACCESS_TOKEN_ID" \
    --header "X-Crystallize-Access-Token-Secret: ACCESS_TOKEN_SECRET"
```

> Enabling `exposeWrite` only makes the tools available — the access token's user must also have the required write permissions in Crystallize for mutations to succeed.

## How the Server Picks Context

The Core API schema and the skill references are too large to send to an agent in full. Two tools can take a
one-sentence description of what the agent is trying to do; the server then asks
[Jev](https://docs.typesafe.ai/), TypeSafe's decision model running on Cloudflare Workers AI, what that task needs.
The server returns only those parts, in a single call.

<JevFlow />

Jev does not write text. It answers yes/no questions with a calibrated probability. The server asks one question per
candidate ("does this task need it?"), all in a single request, and keeps every candidate scoring **0.5 or more**. A task
can therefore get one part or several: "list the last 10 orders" gets `order`, and "find a customer by email and show
their subscriptions" gets `customer` and `subscriptionContract`.

| Tool                        | Input    | Candidates Jev scores                                                          | Returned                                  |
| --------------------------- | -------- | ------------------------------------------------------------------------------ | ----------------------------------------- |
| `fetch-core-graphql-schema` | `intent` | Every Core API domain (84 on a typical tenant), each with its queries and mutations | Combined schema of up to 4 domains        |
| `skills`                    | `task`   | The references of the skills the agent requested (title, intro and headings)   | Main skill document + up to 3 references |

Worth knowing:

- **The agent stays in control.** An exact `domain`, explicit `references` or `includeAllReferences` skip Jev
  entirely. Each answer shows what was picked and how confident Jev was, for example
  `registerOrder (78%), order (63%), customer (54%)`, so the agent can ask for anything missing.
- **Jev never blocks a tool call.** If it takes more than 8 seconds, fails, or picks nothing, the tool returns what it
  returned before Jev: the list of domains, or the skill with its list of references.
- **It is cheap.** A schema pick uses about 12.8k input tokens, and a reference pick about 1.7k. Both cost well under a
  tenth of a cent per call.
- **It is measured.** `bin/eval-domain-selection.ts` and `bin/eval-reference-selection.ts` in the MCP server package
  replay real intents and tasks against the live model. Both currently get every needed part in 12 out of 12 cases.

## Authentication

The MCP Server requires two headers on every request:

| Header                              | Description                          |
| ----------------------------------- | ------------------------------------ |
| `X-Crystallize-Access-Token-Id`     | Your Crystallize access token ID     |
| `X-Crystallize-Access-Token-Secret` | Your Crystallize access token secret |

These credentials are passed through to Crystallize APIs, so the agent operates with the same permissions as the token's associated user.
